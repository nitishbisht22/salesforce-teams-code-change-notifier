Problem Statement

👻

Developers were making silent code changes without informing the QA team during testing

🐛

QA would find a defect → developer would quietly fix it mid-session

🗣️

Developer would then claim "it was always working"

📭

QA had no real-time proof of when changes occurred

📉

Testing results became unreliable and trust between teams broke down

System Architecture

Every 5 minutes — CodeChangeDetector_0, _5, _10...55
↓
📞
CodeChangeDetector.execute()
Schedulable interface — cannot make HTTP calls directly
↓
🔮
runAsync() — @future(callout=true)
Bridge between Scheduled Apex and HTTP callouts
↓
🔍
checkForChanges()
Core logic — queries, filters, notifies
Read last timestamp from Code_Check_Log__c
HTTP GET → Salesforce REST API → SetupAuditTrail
Filter: Section = Apex Class / Apex Trigger / Flow
Filter: CreatedDate > lastCheckTimestamp
Build message string with Who / What / When
TeamsNotificationService.sendNotification() → HTTP POST → Teams
System.enqueueJob(new SaveLogQueueable()) → save timestamp

Setup Guide

1

Microsoft Teams — Create Incoming Webhook

Open Teams → Target channel → Right click → Manage Channel → Connectors → Incoming Webhook → Configure → Copy URL

2

Remote Site Settings (2 entries)

Setup → Remote Site Settings → New. Create one for your Salesforce org URL and one for https://yourcompany.webhook.office.com

3

Custom Metadata Type — Webhook_Config__mdt

Setup → Custom Metadata Types → New. Add Webhook_URL__c Text field. Add a record with your Teams webhook URL.

4

Custom Object — Code_Check_Log__c

Setup → Object Manager → Create Custom Object. Add Last_Check_Time__c DateTime field.

5

Create all 3 Apex Classes

Developer Console → File → New → Apex Class. Create TeamsNotificationService, CodeChangeDetector, and SaveLogQueueable.

6

Schedule the Jobs

Run the scheduling code in Anonymous Window (Developer Console → Debug → Open Execute Anonymous Window). Jobs run forever automatically.

Apex Classes

1. TeamsNotificationService

apex — TeamsNotificationService.cls 
public class TeamsNotificationService {
    public static void sendNotification(String title, String message) {
        // Webhook URL Custom Metadata se lo
        Webhook_Config__mdt config = [
            SELECT Webhook_URL__c 
            FROM Webhook_Config__mdt 
            LIMIT 1
        ];
        
        String body = JSON.serialize(new Map<String, Object>{
            '@type'      => 'MessageCard',
            '@context'   => 'http://schema.org/extensions',
            'themeColor' => 'FF0000',
            'summary'    => title,
            'sections'   => new List<Object>{
                new Map<String, Object>{
                    'activityTitle'    => '⚠️ Salesforce Code Change Alert!',
                    'activitySubtitle' => 'Someone changed code in Sandbox!',
                    'text'             => message
                }
            }
        });
        
        HttpRequest req = new HttpRequest();
        req.setEndpoint(config.Webhook_URL__c);
        req.setMethod('POST');
        req.setHeader('Content-Type', 'application/json');
        req.setBody(body);
        new Http().send(req);
    }
    
    @future(callout=true)
    public static void sendNotificationAsync(String title, String message) {
        sendNotification(title, message);
    }
}

2. CodeChangeDetector

apex — CodeChangeDetector.cls 
public class CodeChangeDetector implements Schedulable {
    
    public void execute(SchedulableContext sc) {
        runAsync();
    }
    
    @future(callout=true)
    public static void runAsync() {
        checkForChanges();
    }
    
    public static void checkForChanges() {
        // Step 1: Get last check timestamp
        DateTime lastCheck;
        List<Code_Check_Log__c> logs = [
            SELECT Last_Check_Time__c 
            FROM Code_Check_Log__c 
            ORDER BY CreatedDate DESC LIMIT 1
        ];
        lastCheck = logs.isEmpty() ? 
            DateTime.now().addMinutes(-2) : logs[0].Last_Check_Time__c;
        
        // Step 2: Query SetupAuditTrail via REST API
        String query = 'SELECT+CreatedDate,CreatedBy.Name,Action,Section,Display' +
                       '+FROM+SetupAuditTrail+ORDER+BY+CreatedDate+DESC+LIMIT+50';
        HttpRequest req = new HttpRequest();
        req.setEndpoint(URL.getOrgDomainUrl().toExternalForm() 
            + '/services/data/v59.0/query/?q=' + query);
        req.setMethod('GET');
        req.setHeader('Authorization', 'OAuth ' + UserInfo.getSessionId());
        req.setHeader('Content-Type', 'application/json');
        
        HttpResponse res = new Http().send(req);
        
        if(res.getStatusCode() == 200) {
            Map<String, Object> result = (Map<String, Object>) 
                JSON.deserializeUntyped(res.getBody());
            List<Object> records = (List<Object>) result.get('records');
            
            if(records != null && records.size() > 0) {
                String msg = '';
                DateTime latestChange = lastCheck;
                
                for(Object rec : records) {
                    Map<String, Object> record = (Map<String, Object>) rec;
                    String section = (String) record.get('Section');
                    String createdDateStr = (String) record.get('CreatedDate');
                    
                    // Step 3: Filter Apex Class, Apex Trigger, Flow only
                    if(section != 'Apex Class' && section != 'Apex Trigger' && section != 'Flow')
                        continue;
                    
                    // Step 4: Only changes after last check
                    DateTime createdDate = DateTime.valueOfGmt(
                        createdDateStr.replace('T', ' ').replace('Z', ''));
                    if(createdDate <= lastCheck) continue;
                    if(createdDate > latestChange) latestChange = createdDate;
                    
                    Map<String, Object> createdBy = (Map<String, Object>) record.get('CreatedBy');
                    msg += '👤 **Who:** ' + createdBy.get('Name') + ' \n\n';
                    msg += '🔧 **What:** ' + record.get('Display') + ' \n\n';
                    msg += '📁 **Section:** ' + section + ' \n\n';
                    msg += '🕐 **When:** ' + createdDateStr + ' \n\n---\n\n';
                }
                
                if(String.isNotBlank(msg)) {
                    TeamsNotificationService.sendNotification(
                        '⚠️ Salesforce Code Change Alert!',
                        '🔔 *Code Change Detected!*\n\n' + msg);
                }
                System.enqueueJob(new SaveLogQueueable(latestChange));
            }
        }
    }
}

3. SaveLogQueueable

apex — SaveLogQueueable.cls 
public class SaveLogQueueable implements Queueable {
    private DateTime latestChange;
    
    public SaveLogQueueable(DateTime latestChange) {
        this.latestChange = latestChange;
    }
    
    public void execute(QueueableContext context) {
        Code_Check_Log__c log = new Code_Check_Log__c();
        log.Last_Check_Time__c = latestChange;
        insert log;
    }
}

Salesforce Limitations & Workarounds

⚡ Scheduled Apex cannot make HTTP callouts
Why It Happens

Salesforce Governor Limit — Schedulable interface blocks direct HTTP calls for security reasons

Workaround Used

Used @future(callout=true) method as a bridge. Scheduled → @future → HTTP call works!

⚡ @future cannot call another @future method
Why It Happens

Nested @future is strictly prohibited in Salesforce — platform prevents it completely

Workaround Used

Removed sendNotificationAsync() call — used sendNotification() directly since we're already inside @future

⚡ DML + HTTP Callout cannot happen in same transaction
Why It Happens

Salesforce transaction boundary rule — you cannot mix DML operations and HTTP callouts in the same execution context

Workaround Used

Used Queueable class for DML — it runs in a separate transaction after the callout completes

⚡ Custom Metadata cannot be updated via Apex DML
Why It Happens

Custom Metadata is deployment-time only — runtime Apex DML (insert/upsert) is not allowed on it

Workaround Used

Created Custom Object Code_Check_Log__c instead — Custom Objects support all DML operations normally

⚡ SetupAuditTrail Section field not filterable in SOQL WHERE
Why It Happens

Salesforce limitation on this specific object — WHERE clause on Section column throws an error

Workaround Used

Fetched all records via REST API and filtered them in Apex code using if conditions

⚡ Tooling API returning HTML instead of JSON
Why It Happens

Wrong endpoint used — /tooling/query/ requires different authentication than Developer Console session

Workaround Used

Used /query/ endpoint instead — SetupAuditTrail is available in standard Salesforce REST API
